# VlogFlow：本地视频创作应用设计草案

日期：2026-10-16

状态：2026-10-16 用户已认可设计，并授权后续计划、实现和 GitHub 发布自主推进。

项目名：VlogFlow（暂定）；计划使用当前已登录的 GitHub 账户创建独立公开仓库。

## 1. 用户目标与已确认范围

让外部用户下载开源项目，在自己的电脑启动后通过浏览器完成视频创作。用户已经确认第一版采用本地网页应用。

核心流程保持为：

1. 输入创作需求并导入多段视频，分析画面，生成逐镜头脚本；用户审核、修改并确认脚本。
2. 弹出字幕选择框，中文、英文、中英对照三选一。
3. 选择本地参考音频，生成克隆配音、字幕和剪辑成片，预览并下载 MP4。

发布的是可安装、可运行的完整流程。此前样片中由人工完成的画面理解、脚本编排、模型配置和中间文件处理，需要补齐为应用能力。

以下设计选择已获用户认可：独立 Python 应用；优先验收 Apple Silicon Mac；配音语言由脚本决定，字幕选项只决定字幕显示语言；视觉模型支持本地服务或用户配置的 API。

## 2. 实现方式选择

| 方案 | 优点 | 代价 | 结论 |
| --- | --- | --- | --- |
| 独立本地网页应用，复用已验证的算法与处理经验 | 界面可以准确对应三步流程；依赖、数据目录和任务状态可统一管理 | 需要补齐视觉模型接入、脚本编辑与任务系统 | 推荐 |
| 基于 NarratoAI 分支继续开发 | 已有画面分析、模型接入及剪辑功能 | 需要维护已有多用途界面、依赖和升级兼容性 | 备选 |
| 基于 ComfyUI 工作流包装 | 适合已有 ComfyUI 用户扩展节点 | 脚本审核、翻译编辑和新用户安装仍需独立界面 | 暂不采用 |

第一版使用独立 FastAPI 服务和随服务分发的轻量网页界面。前端静态文件随 Python 包安装，用户启动应用不需要另外运行前端构建工具。剪辑通过 FFmpeg/ffprobe 完成；音色克隆采用 Qwen3-TTS；本地语音识别用于参考录音转写和配音时间对齐。

## 3. 用户交互

### 3.1 创建项目与导入素材

- 输入主题、必须包含的事实、希望的风格；可设置中文或英文解说语言，默认中文并记住上次选择。
- 支持多文件选择、拖入文件，以及本地服务所在电脑的文件或目录路径。网页明确区分“上传文件”和“导入本机路径”。
- 展示视频缩略图、时长、画幅和原声信息。导入后为素材分配稳定 ID，不以用户机器上的绝对路径作为脚本中的身份标识。
- 分析每段视频的代表性画面，保留帧的来源时间。模型输出画面描述、可用片段、原声状态与不确定信息。
- 根据需求和画面证据生成脚本。用户提供的价格、时间等事实标记为用户信息；不把无法从画面确认的信息描述成模型观察结果。

### 3.2 脚本审核与修改

以镜头卡片或表格呈现：顺序、来源视频、可用时间范围、画面说明、解说文本、原声策略和预计时长。

用户可以修改文字和选段、调整顺序、添加或删除镜头，并预览对应素材。点击“确认脚本并继续”后，保存不可变的脚本版本和内容摘要，后续配音和字幕均从该版本派生。

返回修改脚本会产生新版本，使受影响的旧字幕、配音和成片失效。正在运行的旧版本任务不能覆盖新版本结果。渲染阶段不会自行改写已审核的解说内容。

### 3.3 字幕语言弹窗

提供单选项：中文、英文、中英对照。

- 配音使用已审核脚本的语言。选择中文字幕不会把英文配音自动改成中文，反之亦然。
- 需要翻译时，以审核后的文本生成对应译文；可展开查看并修正译文。译文修改只影响相应字幕。
- 中英对照使用两行展示；字幕按配音时间对齐，处理换行、安全边距、中文字体和长句拆分。
- 更换字幕语言可以复用已有配音。

### 3.4 参考音色与生成

- 支持上传或填写本地音频路径，至少支持 WAV、MP3、M4A、FLAC。
- 自动检查可解码性、有效语音长度、静音与削波情况，统一采样率。
- 自动转写参考录音，允许用户校正转写文字；这是参考录音的文字，不是成片解说脚本。
- 提供短句试听。用户可以更换参考音频，或直接点击“生成成片”。
- 显示真实阶段：准备模型、生成配音、对齐字幕、剪辑画面、混合声音、渲染和验证。只在可测量的阶段显示百分比。
- 成功后提供 MP4 预览和下载，同时可下载 SRT 与最终脚本。

## 4. 模型与运行方式

### 4.1 画面分析和脚本生成

定义统一视觉与文本模型接口，第一版接入：

- 本地 Ollama 视觉模型服务：从本机抽帧后调用本机服务。
- 用户配置的 OpenAI 兼容多模态接口：配置 endpoint、模型名称和 API key。设置页明确显示该提供方会收到抽样画面和需求文本。

未配置可用视觉模型时，应用提供配置入口和连接测试，不生成伪装成画面分析结果的固定脚本。API 是否计费由所选服务决定，项目不宣传所有配置都完全免费。

模型结果必须经过结构校验：素材 ID 必须存在；起止时间有效且处于源视频内；解说文本非空；选段与素材引用一致。格式错误有有限重试，失败显示具体原因并保留已经完成的素材分析。

### 4.2 音色克隆和语音识别

- Apple Silicon 默认使用 Qwen3-TTS 1.7B Base 的 MLX 量化模型，并固定经过验证的依赖与模型版本。
- Qwen 的参考声音编码、语音生成、波形解码分阶段运行。保留已经验证的文本嵌入按需读取和小块解码，避免所有组件同时占用内存。
- 相邻短句适当组合生成，再按句间停顿切分，减小独立短句生成时的音色波动。缓存记录完整文本、参考音频摘要、模型版本、参数和前后文，不能把其他项目的音频当成通用结果复用。
- 语音识别采用本地模型，先完成参考音频转写，再释放资源进入 TTS；配音生成结束后再做字幕对齐。
- Windows/Linux 预留并实现官方 Qwen PyTorch 后端适配。其硬件要求、安装方式及未实机验证的状态单独说明，不把 Mac 的性能结果扩展为跨平台保证。

代码依赖和模型文件分开安装。模型下载到用户数据目录，支持指定已有模型目录，下载后校验文件完整性。仓库和发行压缩包不嵌入模型权重。

## 5. 剪辑、字幕与音频

- 审核脚本中的起止时间表示允许使用的素材范围。实际画面按配音时长在该范围内截取，并统一为帧时间线。
- 配音超过允许范围时，保留生成结果并提示对应镜头需要缩短文字或扩大选段。不能静默裁掉配音、删除文字或自动加速声音。
- 支持按镜头保留环境声。有可辨认原口播的镜头需要在脚本审核时提示；生成旁白时可降低或关闭该镜头原声，避免同时叠加两段讲话。第一版的配音轨统一来自审核后的解说脚本。
- 画幅默认跟随首个视频；可在项目设置选择竖屏或横屏。混合画幅使用明确的适配策略，避免任意裁掉主体。
- 中间音频使用无损 PCM WAV；采用一致的响度和峰值余量；最后输出 MP4 时编码 AAC。
- FFmpeg 使用参数数组调用。兼容未提供字幕滤镜的安装，通过 Pillow 渲染字幕图层；使用可分发的中文字体并附许可说明。
- 最终输出 H.264/AAC MP4，包含完整性检查、音视频时长检查和字幕边界检查；同时保留便于再次编辑的脚本和 SRT。

## 6. 组件、状态与数据

组件划分：

- 网页与 HTTP API：项目、素材、脚本、设置、任务、下载。
- 项目存储：项目元数据、脚本版本、用户设置、任务与产物关系。
- 素材分析：ffprobe、抽帧、可选原声转写、视觉模型调用。
- 脚本服务：生成、校验、编辑、确认及翻译。
- 配音服务：参考音频预处理、转写、Qwen 后端与缓存。
- 时间线与渲染：音画时长协调、字幕、环境声混合与 MP4 输出。
- 作业执行器：顺序运行资源密集任务，报告进度、取消、重试和恢复。

使用本地 SQLite 保存状态，文件按项目 ID 与版本存放在用户数据目录。服务默认只监听本机地址；凭据保存在本地配置中，日志输出隐去凭据。

核心状态为：草稿 → 分析中 → 等待脚本审核 → 已确认脚本 → 字幕就绪 → 音色就绪 → 生成中 → 完成。失败、取消和资源不足保留在所属阶段，不把它们标成完成。

每个阶段生成可验证的产物记录。重启后可恢复已完成阶段；只有缓存输入摘要相符时才复用。失败或取消时只终止本任务创建的子进程。

## 7. 内存与错误处理

- 串行运行视觉模型、语音识别、TTS 和渲染中的资源密集阶段；本地视觉服务请求结束后释放其模型占用。
- 启动前检查可用内存、模型状态、磁盘空间和 FFmpeg。模型与后端采用各自经过验证的资源预算。
- 持续监测可用内存、任务内存和新增交换内存，达到保护阈值终止当前工作进程，保留此前的结果，并提供重试入口。
- 用户明确看到“等待资源”和“运行中”的区别；不会永久等待而无提示。
- 模型下载失败、接口认证失败、参考音频无有效语音、无效片段、字幕生成失败和渲染失败分别给出可操作的信息。
- 参考音色的主观相似度由试听判断，不用自动听写通过或波形相关性充当音色相似度评分。

独立仓库包含源码、安装和启动说明、中英文 README、配置示例、许可证、第三方声明、测试、合成测试素材、示例脚本和版本记录。

项目代码建议使用 MIT 许可证。引用或改写第三方代码时保留其许可与归属；模型许可与应用代码许可分别说明。FFmpeg 作为运行依赖安装，第一版不随应用打包 FFmpeg 二进制。

公开内容使用合成测试素材；真实视频、用户参考录音、克隆音频、用户路径、密钥、模型缓存和任务产物保留在本地数据目录，并由忽略规则与发布文件检查共同隔离。

完成测试后，在用户当前 GitHub 账户下创建公开仓库，发布首个可运行版本。README 明确标注实际验证的系统、功能、资源要求与剩余限制。

## 9. 验收标准

1. 干净环境可按文档安装、启动，并在浏览器完成整条流程；模型配置和下载步骤有明确指引。
2. 导入多个视频后，脚本包含真实素材引用和有效时间范围，可在界面预览和修改。
3. 修改并确认的脚本文字用于配音，字幕来自同一版本；修改后不复用旧版本的错误结果。
4. 中文、英文、中英对照均可独立导出，切换字幕语言不无故重复生成声音。
5. 本地路径和文件上传两种参考音频输入都可生成克隆配音，转写可以校正。
6. 使用本机现有真实素材做端到端验证；公共 CI 使用合成素材和显式测试模型替身，不把替身测试描述为真实模型已通过。
7. 对脚本版本失效、素材越界、配音过长、取消、内存保护、重试、字幕排版和 MP4 完整性建立有实际意义的测试。
8. 浏览器检查完成脚本编辑、语言单选、音频选择、任务进度与下载；验证不存在遗留的个人路径或固定烧烤脚本。
9. 公共发布前检查实际提交文件，并从打包后的干净项目执行安装及冒烟测试。

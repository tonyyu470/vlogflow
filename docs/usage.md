# 使用说明

## 模型准备

启动命令与安装见 README。模型和程序代码分别安装。

默认 MLX 模型是 `mlx-community/Qwen3-TTS-12Hz-1.7B-Base-8bit`，固定 revision 为 `e7dd0585652209fa0d7783659aad4e8a324de11c`。参考声音编码、语音 token 生成和波形解码分别在独立进程中运行，文本嵌入只读取需要的行，波形以 20 帧分块、25 帧上下文解码。并非降低声音速度或调整音高的后处理。

模型清单保存在 `src/vlogflow/assets/*-manifest.json`。`vlogflow models download` 下载固定版本并校验已公布的权重 SHA-256；已有模型路径也会校验。网络受限时，可以先通过 Hugging Face 的受信任镜像下载相同 revision，再填写本地路径。不要关闭 TLS 或跳过文件校验。

若使用自配 OpenAI 兼容服务，先选择对应提供方，填写其 base URL、模型和 API Key。`/chat/completions` 会附加在 base URL 后面；例如提供方文档要求 `https://example.org/v1/chat/completions`，应填 `https://example.org/v1`。连接测试只验证文本 JSON 请求；图片能力还需要用短视频验证。

## 1. 素材与脚本

在需求中写明可以使用的事实，例如价格、地点、时间、希望强调的内容。视觉模型只能看到抽样画面，不应被当作事实核验工具。

点击选择视频、拖入文件，或粘贴本机文件/文件夹路径。文件夹只导入直接包含的支持格式，不递归扫描。导入会复制素材到项目数据目录，原文件不会被修改。相同内容不会重复添加。

点击「分析画面，生成脚本」。任务逐段分析，保留已完成分析缓存。失败时查看阶段与错误，修正配置后重试。

逐镜头编辑：

- 来源视频、允许起点与终点，均以秒为单位。
- 解说文字：配音按此生成，不会在渲染时自动改写。
- 环境声：有本人原口播的镜头建议关闭原声；普通环境声可以适当保留。
- 顺序、增删、画面说明和原片预览。

确认脚本会创建不可变版本。返回修改后必须重新确认；已开始的旧任务不能覆盖新版本。

## 2. 字幕语言

在弹窗中单选中文、英文或中英对照。解说语言保持步骤 1 的选择。

若需要另一种语言，点击「生成字幕译文」，或直接填写。生成后可以校对价格、地名、专有词。原语言字幕来自已审核脚本，在此处只读；需要修改原语言时返回脚本步骤。

切换字幕语言和修改译文会使旧视频失效，但不改变已生成的配音。中英对照会自动分段并换行；长句仍建议在脚本中拆成更短的镜头。

## 3. 音色与生成

上传 WAV、MP3、M4A、FLAC，或提供本机路径。建议录制 4–30 秒连续独白，安静环境、自然语速、避免背景音乐。录音不是越响越好，削波严重会被拒绝。

自动转写完成后，核对「参考录音文字」。这里填写参考录音实际说的话，不是成片脚本。也可在导入前直接提供录音文字，跳过自动转写。参考录音文字影响克隆质量。

「试听第一句」用于主观判断音色。成片生成时相邻短句会组合为上下文后再对齐拆分，试听与整片可能存在轻微差异。

选择画幅并生成 MP4。阶段包含准备模型、克隆配音、识别与对齐、画面剪辑、渲染、完整性校验。应用只报告实际阶段，不显示虚构的总体百分比。

完成后播放成片并下载 MP4、SRT 和 JSON。音色相似度由试听判断，自动听写通过不代表相似度达到某个分数。

## 失败、取消与重试

| 提示 | 处理 |
|---|---|
| 可用内存不足 / 内存保护 | 保存其他工作并完全退出暂时不用的应用，然后点击重试。不会永久等待或自动重新加载模型。 |
| 模型文件缺失或哈希不符 | 使用模型下载命令安装对应固定版本，或检查设置中的目录。 |
| 接口不可达 / HTTP 401 等 | 启动 Ollama，或检查 API endpoint、模型名、密钥。错误不会回显密钥。 |
| 脚本 JSON / 素材引用无效 | 模型已有限重试；调整模型或简化需求后重试，也可手动写脚本。 |
| 配音超过允许范围 | 生成的音频缓存保留；扩大该镜头选段，或缩短解说并重新确认。 |
| 配音听写与脚本不匹配 | 试听缓存、改善参考录音/文字或简化解说。程序不会静默换词。 |
| 字幕缺少译文 | 回到第二步生成、填写并保存对应译文。 |
| 中断 / 取消 | 已完成缓存保留；重试使用当前项目版本。 |

字幕、声音和成片依赖不同输入摘要。旧缓存不按文件名猜测复用。模型参数、参考录音、录音文字、上下文或模型版本改变时会重新生成。

## 其他系统（实验性）

Windows/Linux 后端通过官方 `qwen-tts` 实现，不是 MLX。此适配器尚未在 Windows/Linux/CUDA 上实机验证。建议独立 Python 环境，按 PyTorch 官方文档安装符合显卡和驱动的构建；CPU 推理可能很慢。

```bash
python -m venv .venv
# Linux: source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -e '.[torch,asr]'
vlogflow models download qwen-torch
vlogflow models download asr
vlogflow serve
```

另行安装并将 FFmpeg/ffprobe 加入 PATH。视觉服务仍可选择 Ollama 或自配 API。设置中将音色后端选为 PyTorch；若环境独立，填写 TTS Python 的绝对路径。PyTorch 适配使用保守的 10 GiB 主机可用内存门槛，不代表 GPU 显存已经足够，也不承诺 16 GB Mac 上运行 PyTorch 后端。

## 数据目录与清理

通过 `vlogflow doctor` 查看数据位置，或在启动前设置 `VLOGFLOW_DATA_DIR`。应用默认只监听 `127.0.0.1`。同一数据目录只允许一个 CLI 服务实例。

`projects/` 包含导入副本、录音、任务日志和成片；`cache/` 包含分析、ASR、克隆配音和模型组件；`models/` 保存模型；SQLite 保存项目与版本。缓存包含私人声音，不能作为公开示例提交。停止程序并备份需要的项目后，可以手动清理不再需要的缓存；下一次使用会重新生成。
